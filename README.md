# Dolos

浏览器里的 3D 酒馆 + 德州扑克。走进大厅、挑一张桌子坐下，剩下的位置由 AI 补位。

**线上 demo**：https://parthenon-labs.github.io/dolos/

> 虚拟筹码，不可充值提现。

---

## 现在能玩到什么

- **一座两层酒馆**，可自由走动、上下楼、靠近空位坐下。全程零美术资源，
  几何体 + 光照 + 后处理撑起来的
- **完整的德州扑克**：盲注、四条街、加注规则、all-in、边池、摊牌
- 五个启发式 bot，各有不同的松紧度，会弃牌、会按牌力加注、偶尔诈唬

## 跑起来

```bash
npm install
npm run dev        # http://localhost:5173
npm run check      # 规则引擎的全部检查
npm run build
```

[**一个人写代码时，怎么知道它是对的**](docs/how-i-know-it-works.md) ——
这个项目里几乎每个难缠的 bug 都长一个样：代码看着是对的、测试是绿的、也不报错。
这篇讲我最后是靠什么抓住它们的（其中三条是我自己的测试用例写错了，而代码是对的）。

## 这个项目里值得看的部分

### 牌力评估不用查表

`src/poker/evaluate.ts` 穷举 C(7,5)=21 种五张组合打分取最大。
查表法快几十倍，但一张十几万项的表**没法用眼睛验证**，
而这是决定谁拿钱的代码。21 次组合每手不到 10 微秒，瓶颈根本不在这。

### 兜住分池 bug 的是不变量，不是用例

用例只能覆盖你想到的情况。真正的网是两条：

- **筹码守恒** —— 一手牌前后所有人筹码总和必须精确相等。分错钱几乎必然破坏它
- **边池样本量** —— all-in 在均匀随机对局里出现得不够密，所以刻意用参差不齐的
  起始筹码把它逼出来。现在 4000 手随机牌局里有 2698 手产生边池，
  这个数字掉下去就说明覆盖没了

`settle()` 里的守恒断言是**抛错而不是记日志**：分池写错时它立刻炸，
而不是等玩家发现自己少了钱。

### 隐藏信息在投影层就切干净

`project(state, seat)` 是发给玩家的唯一出口，别人的底牌在这里就被抹掉了，
不是靠前端不渲染。整个项目只有一处隐藏信息，正因如此更不能靠自觉 ——
一旦漏，客户端改个变量就能看穿全场。

### 光源预算

大厅里有四十多盏灯，全开是 9.7 FPS。
`src/scene/LightBudget.tsx` 只让最近的 N 盏可见，且**可见数量恒定** ——
数量变化会触发 three.js 重编译着色器，比多点几盏灯贵得多。
改完 70.8 FPS。

## 状态

也就是说牌堆在客户端内存里，联机对战之前它只能一个人打 bot。
